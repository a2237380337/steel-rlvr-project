# Qwen3.5 低频钢种数值 DPO：正式实验报告

## 结论先行

项目已在单张 AMD RX 7900 XT 上完成 Qwen3.5-0.8B-Base 的 LoRA-SFT、普通 DPO、钢种频次感知 DPO 和四模型统一评测。

- LoRA-SFT 总体 MAE 0.6486，相对 Base 0.6864 降低 5.52%；
- 普通 DPO 总体 MAE 0.6488，相对 SFT 回退 0.03%；
- 频次感知 DPO 与普通 DPO 的总体、Macro 和 Worst-group MAE 完全相同；
- 两个 DPO 权重文件不同，但冻结测试的 1,017 个贪心数值预测完全一致；
- 所有模型数值可解析率 100%、物理越界率 0，DPO 严格 JSON 率约 99.1%；
- 所有总体 R² 仍为负，结果不支持替代 KD-Steel 或用于在线控制。

本项目最重要的结论不是“DPO 提升了性能”，而是偏好训练准确率提升没有自动转化为连续值生成误差下降。

## 研究问题

1. DPO 能否在不使用低频测试钢种标签的条件下继续改善 SFT？
2. 只提高训练集中较少见钢种的偏好对抽样概率，能否改善未见钢种的 Macro/Worst-group 误差？

## 数据与偏好对

数据审计后保留 34,317 条真实记录、63 个钢种。44 个常见钢种按 8:2 进入训练/验证，19 个频次低于 50 的钢种整组留作测试。每条记录拆成三个道次：

| 分区 | 原始记录 | 道次样本 |
|---|---:|---:|
| Train | 27,182 | 81,546 |
| Validation | 6,796 | 20,388 |
| Test | 339 | 1,017 |

偏好对只由 train/validation 构造。`chosen` 是真实目标的严格 JSON；`rejected` 保持格式不变，把数值偏移 `0.5/1.0/1.5 × train_MAD`。因此偏好不能靠 JSON 格式差异判断，也不会读取测试标签。

正式 DPO 各抽 3,000 条训练对和相同的 768 条验证对。普通组均匀抽样；频次感知组使用：

```text
w_g = clip(sqrt(200 / n_g_train), 1, 2)
```

频次感知抽样把训练集中 `w_g > 1` 的样本占比从 7.93% 提高到 10.63%，平均钢种训练频次从 2877.23 降到 2795.10。

## 环境与训练

| 项目 | 配置 |
|---|---|

| 模型 | Qwen/Qwen3.5-0.8B-Base，固定 revision |

| SFT | 3,000 条，300 steps，LoRA rank 16 / alpha 32 |

| 训练组 | Train loss | Validation loss | 偏好准确率 | 时间 | 峰值显存 |
|---|---:|---:|---:|---:|---:|

训练诊断显示 DPO 学会了区分 chosen/rejected，但这不等价于测试集生成误差下降。

四模型使用相同测试 SHA256 `6922b193...53a49`、相同样本 ID SHA256 `16688d73...13139` 和相同评测源码 SHA256 `041ade8e...9f85`。

## 诊断

1. 主要收益来自 SFT：模型先学会输出格式和粗粒度数值范围。
2. DPO 相对 SFT 只改变 4/1,017 个数值预测，说明固定偏移负样本对当前策略过于容易。
3. 两个 DPO adapter SHA256 分别为 `07a1c3fe...ebfa` 与 `d052e8e7...9a59`，证明训练结果并非同一文件；但贪心解码把参数差异映射为完全相同的数值输出。
4. 频次感知抽样提高了较少见训练钢种的占比，却没有改善完全未见钢种，说明训练内长尾重采样不能自动解决类别冷启动。
5. DPO 的严格 JSON 率略降，说明 chosen/rejected 始终同格式时，偏好目标不会额外强化格式约束。

若继续实验，应改用当前策略生成且数值更接近的难负样本，并预注册多个随机种子与验证选择规则。当前仓库不把这些后续设想写成已完成工作。
